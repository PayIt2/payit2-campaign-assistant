# PayIt2 Plugin 2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks marked **Brian** are his to do; Claude prepares the exact steps and checks the result.

**Goal:** Release the Campaign Assistant as plugin `payit2` (display name PayIt2) version 2.0.0, passing `claude plugin validate --strict` and the Claude directory's blocking checks, with both marketplaces pinned to it.

**Architecture:** All plugin changes stay in `plugin/`. `release.sh` stops matching the marketplace entry by name and matches it by source (repo and folder), so one release both renames the entry and moves its pin. Behavior is unchanged apart from the command prefix.

**Tech Stack:** bash, Python 3 standard library, Node 24 with vitest (`tests/`), Claude Code CLI (`claude plugin validate`), `gh`.

**Spec:** `docs/specs/2026-11-08-claude-chatgpt-publishing-design.md`, Part 1 and decisions D3 and D6. This is plan 1 of 4: the server change (Part 2), plugin 2.1.0 with the ChatGPT package (Part 3) and the install funnel (Part 5) each get their own plan.

## Global Constraints

- Plugin id `payit2`, display name `PayIt2`. The repo keeps its name, `PayIt2/payit2-campaign-assistant`.
- The hooks stay (D3). This plan only quotes their paths and removes `jq`.
- Release zip file names stay as they are (`payit2-campaign-assistant.zip` here, `payit2-campaign-assistant-plugin.zip` in the public marketplace), because payit2.com links to them.
- Copy: "Organizer", never "User"; no em dashes or en dashes anywhere in `plugin/` (a test enforces it).

Conventional commits. **No `Co-Authored-By` trailer.** Commit as `brian@payit2.com`. PR descriptions end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Tests: `cd tests && npm test` (unit) must pass before every commit that touches `plugin/`, `scripts/` or `release.sh`.

- [ ] **Step 3: Write `scripts/bump_pin.py`**

```python
#!/usr/bin/env python3
"""Sets the Campaign Assistant's pin in a marketplace index.

Finds the entry by its source (repo and folder), not by its name, so the 2.0.0 rename from
payit2-campaign-assistant to payit2 renames the entry in the same step that moves the pin.
"""
import json
import sys

REPO = "PayIt2/payit2-campaign-assistant"
FOLDER = "plugin"


def bump(path: str, name: str, sha: str) -> None:
    with open(path) as f:
        data = json.load(f)
    for plugin in data.get("plugins", []):
        source = plugin.get("source", {})
        if source.get("url") == REPO and source.get("path") == FOLDER:
            plugin["name"] = name
            source["sha"] = sha
            break
    else:
        sys.exit(f"no {REPO} ({FOLDER}/) entry in {path}")
    with open(path, "w") as f:
        json.dump(data, f, indent=2)
        f.write("\n")


if __name__ == "__main__":
    if len(sys.argv) != 4:
        sys.exit("usage: bump_pin.py <marketplace.json> <plugin name> <sha>")
    bump(sys.argv[1], sys.argv[2], sys.argv[3])
```

```bash
#!/bin/bash
# UserPromptSubmit hook: spot a PayIt2 campaign link in the organizer's message and add its type
# and slug to the turn. Plain shell only (no jq), so it runs on any Mac or Linux machine.
# Input: the hook's JSON on stdin. Output: context for Claude, or nothing.
INPUT=$(cat)
URL=$(printf '%s' "$INPUT" | grep -oiE 'payit2\.com/(fundraiser|event|group)/[A-Za-z0-9_-]+' | head -n 1)
[ -z "$URL" ] && exit 0
TYPE=$(printf '%s' "$URL" | cut -d'/' -f2)
SLUG=$(printf '%s' "$URL" | cut -d'/' -f3)

cat <<EOF
[PayIt2 Campaign Detected: https://$URL]
Type: $TYPE
Slug: $SLUG

If PayIt2 tools are available, call get_campaign_overview with the slug or campaign ID to fetch live stats before responding. If they are not, ask the organizer for the current numbers; the skills work fine in standalone mode.

If the organizer hasn't said what they want, ask which command to run:
  /check-in  - health score and prioritized action plan
  /promote   - promotion strategy and content calendar
  /engage    - participant messages (thank-yous, updates, re-engagement)
EOF
```

PayIt2 helps organizers run fundraisers, events and group payments. This plugin brings PayIt2
